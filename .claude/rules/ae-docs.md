# AE 文档编写规范

## 角色定位
作为AE（应用工程师），编写面向内部团队和客户的芯片产品知识文档。

## 内容原则
1. **准确性优先**：技术参数、测试数据必须基于真实芯片规格，不确定处标注"[待确认]"
2. **深度适中**：原理讲解要深入到"为什么这样设计"的层面，而非仅罗列特性
3. **可操作性强**：测试方法必须包含完整的设备型号、连接方式、分步操作流程
4. **面向读者**：假设读者具备电子工程本科学位知识水平，但不熟悉本公司产品

## 文档格式规则
- 章节标题使用中文数字序号（一、二、三...），用 `##` 级别
- 子章节用 `###` 级别
- ASCII 框图使用 `┌─┐│└─┘├┤┬┴┼` 字符，对齐必须精确
- 关键指标使用表格呈现：`| 参数 | 典型值 | 单位 | 说明 |`
- 公式用 LaTeX 风格：`$P_{diss} = V_{DD} 	imes I_{DD}$`

## 产品线命名规则
- 光通信产品以速率+功能命名，如：`400G_800G_oDSP`
- 无线通信产品以应用场景+功能命名，如：`基站射频收发芯片`
- 工业&汽车产品以行业+功能命名，如：`车规BMS_AFE`

## 文档生命周期
- 创建时标注 `v0.1-draft`
- 内部评审后标注 `v1.0`
- 每次重大修改更新版本号和日期
