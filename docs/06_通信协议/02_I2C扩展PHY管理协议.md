# I2C 扩展 PHY 管理协议详解

> **面向角色**: AE (应用工程师)
> **文档版本**: v1.0
> **更新日期**: 2026-07-18

> I2C 物理层 + 自定义寄存器访问协议 — 5-bit PHY 地址 + 21-bit 寄存器地址 + 16-bit 数据。基于用户提供的时序图解析：5-bit PHY_AD + 21-bit 寄存器地址 + 16-bit 数据 + BURST 突发模式。

---

## 一、背景与应用定位

本文档描述的是一种基于标准 I2C 物理层但帧格式做了大幅扩展的自定义协议。它保留了 I2C 的 2 线（SCL + SDA）和字节级 ACK 机制，但把 I2C 原有的 7/10 位设备地址 + 8 位数据寄存器模式，扩展为 **5-bit PHY 地址（PHY_AD）+ 21-bit 寄存器地址（AD[20:0]）+ 16-bit 数据（DA[15:0]）** 的结构，并新增了 WR/RD 方向位和 BURST 突发位。

> **一句话定位**：这是一种"I2C 物理层 + 类 MDIO 语义"的 PHY/收发器管理协议。它用 I2C 的硬件资源（FPGA/SoC 上常见的 I2C 控制器）来实现对 PHY 大寄存器空间的 16-bit 读写，本质上是把"PHY 地址 + 寄存器地址 + 16-bit 数据"映射到了 I2C 的字节帧上。

### 协议定位

| 维度 | 说明 |
|------|------|
| 物理层 | 标准 I2C（SCL/SDA，开漏，上拉，字节 ACK） |
| 数据链路层 | 自定义帧格式，非标准 I2C 设备地址格式 |
| 功能定位 | 管理 PHY、SerDes、收发器（Transceiver）等带大寄存器空间的器件 |
| 典型特征 | 一次寄存器访问最多拆成 8 个字节（PHY_AD + RSV + WR/RD + 地址 3 字节 + 数据 2 字节 + 可选突发数据） |

### 典型应用场景

- FPGA 高速收发器管理：Xilinx/AMD、Altera/Intel 的高速以太网/光纤子系统通过 I2C 访问外部 PHY 或内部 SerDes 寄存器
- 多速率 PHY 的扩展配置：10G/25G/40G/100G PHY 寄存器空间大，标准 7-bit I2C 地址不够用
- 缺 MDIO 的 SoC/FPGA：当芯片没有专用 MDIO 控制器，但 I2C 资源丰富时，用此协议复用 I2C
- 光模块 / SFP-DD / QSFP 管理：部分高端光模块用 I2C 做扩展寄存器访问，代替 MDIO
- 背板 / 交换机 PHY 阵列：通过 I2C 总线管理多颗 PHY，地址空间超过标准 I2C 的 7/10-bit 限制

### 与标准 I2C 的核心区别（总览）

| 维度 | 标准 I2C | I2C 扩展协议 |
|------|----------|--------------|
| 物理层 | 2 线 SCL/SDA，开漏，上拉 | 完全相同 |
| 设备地址 | 7 bit（0-127）或 10 bit | 5 bit PHY_AD（0-31） |
| 寄存器地址 | 通常 1 字节（0-255），大容量 EEPROM 可 2 字节 | 21 bit（AD[20:0]），可寻址 2M 寄存器 |
| 数据位宽 | 每字节 8 bit，通常逐字节访问 | 16 bit（2 byte），即 DA/RDA[15:0] |
| 方向/读写位 | 1 bit（R/W，0=写，1=读）与设备地址合并 | 1 bit WR/RD（0=写，1=读），独立帧段 |
| 突发模式 | 支持连续读写（页写 / 顺序读） | bit 1 读写复用：写帧 AD0/DA1 区分地址帧/数据帧，读帧 BURST 控连续读 |
| ACK/NACK | 每字节后 1 bit | 每字节后 1 bit ACK；读操作末字节用 NACK 终止 |
| 主机角色 | 多主仲裁、从机可拉低 SCL（clock stretching） | 通常单主，从机被动响应，可支持 clock stretching |

> **命名提示**：该协议在业界常被称作"扩展 I2C PHY 管理协议"、"I2C 访问 MDIO 映射"、"I2C 大地址寄存器访问协议"。它并非 Philips/NXP 标准 I2C 协议的官方扩展，而是 FPGA、高端 PHY 和收发器厂商为特定应用场景定义的自定义协议。因此实际实现时必须严格参考对应芯片/IP 的 datasheet，帧顺序和字段可能略有差异。

## 二、核心工作原理

该协议在标准 I2C 的 SCL/SDA 物理层之上，定义了一个固定结构的寄存器访问帧。所有通信由主机发起，主机在 SDA 上按 MSB 先发送出字段，从机在每个字节（8 bit）的 SCL 第 9 个时钟脉冲期间拉低 SDA 以产生 ACK；主机在收到 ACK 后继续发送下一字节。一次完整寄存器访问通常分为"地址/命令段"和"数据段"。

### 核心概念

| 术语 | 全称 | 说明 |
|------|------|------|
| PHY_AD | Physical Address | 5 位 PHY 物理地址（0-31），用于总线区分不同 PHY，与 MDIO 的 PHYAD 对应 |
| AD[20:0] | Register Address | 21 位寄存器地址，由 AD[20:16] + AD[15:8] + AD[7:0] 三段组成，最大寻址 2,097,152 个寄存器 |
| DA[15:0] | Data | 写操作数据，16 位（2 字节） |
| RDA[15:0] | Read Data | 读操作数据，16 位（2 字节） |
| WR/RD | Write / Read | 1 位方向位，WR=0 表示写，RD=1 表示读 |
| BURST | Burst Mode | 突发模式位，BURST=0 单次 16-bit 数据，BURST=1 连续多 16-bit 数据 |
| RSV | Reserved | 保留位，图中出现 1 bit（RSV）和 3 bit（RSV[2:0]），应写 0/按 datasheet 配置 |
| ACK | Acknowledge | 每字节后 1 bit，从机拉低 SDA 表示应答 |
| NACK | Not Acknowledge | 主机读数据时，最后一字节后释放 SDA，由从机读到高电平，表示传输终止 |

### 写操作（Write）

1. **发送 START 条件**：主机拉低 SDA 同时保持 SCL 高，产生 I2C START 条件
2. **发送命令字节**：PHY_AD[4:0] + RSV + AD0/DA1 + WR=0，共 8 bit，然后等待从机 ACK。其中 AD0/DA1 为 1 bit 地址帧/数据帧选择位：DA1=1 数据帧（地址+数据，常规写寄存器），AD0=0 地址帧（只写地址不发数据，配合读操作预设指针）
3. **发送地址高 5 位**：RSV[2:0] + AD[20:16] + 1 bit（凑成 8 bit），然后等待 ACK
4. **发送地址中 8 位**：AD[15:8]，然后等待 ACK
5. **发送地址低 8 位**：AD[7:0]，然后等待 ACK
6. **发送 16-bit 数据**：先 DA[15:8]，再 DA[7:0]，每字节后等待 ACK
7. **发送 STOP 或继续突发**：单写时发送 STOP；DA1=1（数据帧）时可继续发送更多 16-bit 数据，地址自动 +1，类似页写；AD0=0（地址帧）时不发数据段，仅设定地址指针供后续读操作使用

### 读操作（Read）

1. **发送 START 条件**：主机产生 I2C START
2. **发送命令字节**：PHY_AD[4:0] + RSV + BURST + RD=1，共 8 bit，等待从机 ACK
3. **读取数据高 8 位**：主机释放 SDA，从机驱动 RDA[15:8]，主机在 SCL 上产生 8 个时钟并 ACK
4. **读取数据低 8 位**：从机驱动 RDA[7:0]，主机在最后一个字节后发送 NACK
5. **发送 STOP 或继续突发**：单读时发送 STOP；BURST=1 且需继续读时，先不发送 STOP，而是继续下一个 16-bit 读（每 2 字节为一组）

> **关键点**：写操作为单帧合并式（地址+数据同事务），读操作无独立地址段！写帧在一个 I2C 事务内同时携带 21-bit 寄存器地址和 16-bit 数据，一次完成写入。而读帧命令字节后直接是从机返回的数据，没有地址段——这意味着读操作通常需要"两步读"：先发起一次写帧写入目标地址（可不带数据段或忽略数据），再发起读帧触发数据返回。这与标准 I2C 寄存器读的"先写地址再 Repeated START 读"模式一致。

## 三、核心模块深度解析 — 帧结构与字段详解

时序图清晰展示了一个自定义 I2C 应用层协议。下面将写帧和读帧的每个字段逐一定义，并给出与 I2C 物理层的字节对应关系。

### 3.1 写操作帧（scl_write / sda_write）

写帧由"命令段" + "地址段" + "数据段"组成，采用单帧合并式结构——地址与数据在同一个 I2C 事务（一次 START→STOP）内完成发送，每个字节后都有从机 ACK。图中显示 3 bytes 地址后接 16-bit 数据，并提示 DA1=1 时可继续发送更多数据（地址自动递增）。当 AD0=0 时为纯地址帧，只发地址段不发数据段，用于设定读操作的地址指针。

| 字段 | 位宽 | 写帧值 | 说明 |
|------|------|--------|------|
| PHY_AD[4:0] | 5 | 00000~11111 (0-31) | PHY 物理地址，寻址目标从机 |
| RSV | 1 | 0 | 保留位，通常写 0 |
| AD0/DA1 | 1 | 1（写数据） | 地址帧/数据帧选择位：AD0=0 地址帧，DA1=1 数据帧（地址+数据单帧合并，支持连续写、地址自动+1）；写寄存器时置 1 |
| WR/RD | 1 | 0（写） | 方向位：0 表示写，1 表示读 |
| ACK | 1 | 从机拉低 | 从机应答：SDA 被拉低 |
| RSV[2:0] | 3 | 000 | 3 位保留位，通常写 0 |
| AD[20:16] | 5 | 可变 | 寄存器地址 bits 20-16（高 5 位） |
| AD[15:8] | 8 | 可变 | 寄存器地址 bits 15-8（中 8 位） |
| AD[7:0] | 8 | 可变 | 寄存器地址 bits 7-0（低 8 位） |
| DA[15:8] | 8 | 可变 | 写数据高 8 位 |
| DA[7:0] | 8 | 可变 | 写数据低 8 位 |

### 3.2 读操作帧（scl_read / sda_read）

读帧相比写帧省去了地址段，命令字节直接包含 PHY_AD + BURST + RD=1，随后从机返回 2 字节数据。若 BURST=1，可继续返回多组 2 字节数据（地址自动递增）。

> 注意：BURST 位与写帧中的 AD0/DA1 位处于命令字节的同一位置（bit 1），是读写方向的复用位——写操作时区分地址帧/数据帧，读操作时控制是否连续突发读。读帧无地址段，是因为地址已由前序的 AD0=0 地址帧预设。

| 字段 | 位宽 | 读帧值 | 说明 |
|------|------|--------|------|
| PHY_AD[4:0] | 5 | 00000~11111 (0-31) | PHY 物理地址，寻址目标从机 |
| RSV | 1 | 0 | 保留位 |
| BURST | 1 | 0=单数据 / 1=突发 | 突发模式位，控制是否连续返回多组 16-bit 数据 |
| RD | 1 | 1 | 方向位：1 表示读 |
| ACK | 1 | 从机拉低 | 命令字节后的从机应答 |
| RDA[15:8] | 8 | 从机输出 | 读数据高 8 位 |
| ACK | 1 | 主机拉低 | 数据高字节后主机发送 ACK，表示继续读 |
| RDA[7:0] | 8 | 从机输出 | 读数据低 8 位 |
| NACK | 1 | 主机释放 | 数据低字节后主机发送 NACK（释放 SDA），表示读完成 |

**读操作地址机制说明**：读操作遵循"两步读"模式，利用 AD0=0 地址帧预设地址指针：

1. **第一步（地址帧，AD0=0）**：先发起一次地址帧（命令字节中 AD0=0、WR=0），只发送 21-bit 寄存器地址（AD[20:0]），不发送数据段，用于设定 PHY 内部地址指针
2. **第二步（读帧，RD=1）**：再发起读帧（RD=1），从机自动返回当前指针所指寄存器的 16-bit 数据。若 BURST=1，地址自动递增，可连续读取后续寄存器

这正是 AD0/DA1 这一位的核心用途：DA1=1 用于写数据（地址+数据单帧合并），AD0=0 用于只写地址（配合读操作预设指针）。在调试时若读帧返回数据不符合预期，首先应确认是否需要"先发地址帧再读"的两步操作。

### 3.3 AD0/DA1 与 BURST：地址帧/数据帧选择详解

命令字节的 bit 1 是读写方向复用位：写操作时为 AD0/DA1（地址帧/数据帧选择），读操作时为 BURST（突发读控制）。

**AD0/DA1 命名含义：**

- AD0：AD = Address（地址），0 = 该位值为 0 → **地址帧**，只发地址段 AD[20:0]，不发数据段；用于设定读操作的地址指针
- DA1：DA = Data Access（数据访问），1 = 该位值为 1 → **数据帧**，地址段 AD[20:0] + 数据段 DA[15:0] 一起发送；用于常规写寄存器

命名直接对应地址字段 AD[20:0] 和数据字段 DA[15:0] 的缩写，后缀 0/1 表示该位的值。

| bit 1 值 | 写操作（AD0/DA1） | 读操作（BURST） |
|----------|-------------------|-----------------|
| 0（AD0） | 地址帧：只发地址段不发数据段，用于设定读操作的地址指针（配合两步读） | 单次读：只读取一个 16-bit 数据，低字节后 NACK 终止 |
| 1（DA1） | 数据帧：地址+数据单帧合并发送，支持连续写多个 16-bit 数据（地址自动 +1，类似页写） | 突发读：读取一个 16-bit 后主机发送 ACK 继续，从机自动返回下一个地址 +1 的 16-bit；主机最后发送 NACK 终止 |

> **批量访问优势**：对于批量读写 PHY 错误计数、寄存器 dump、日志收集等场景，DA1=1 连续写 / BURST=1 连续读可以显著减少总线开销。按标准 I2C 100 kHz 计算，单次读一个 16-bit 数据约需 18 字节 × 90 µs ≈ 1.62 ms；突发模式下后续每 16-bit 只需约 2 字节 × 90 µs ≈ 0.18 ms，效率提升近 8 倍。写操作同理：连续写可省去重复发送 3 字节地址段的开销。

### 3.4 字节与位映射（I2C 物理层视角）

从 I2C 总线角度看，协议最终由若干 8-bit 字节 + ACK 组成。下面给出写帧的字节级映射：

**写帧字节映射（MSB 先发，每个字节后 1 bit ACK）：**

```
Byte 0  [命令字节]:   | PHY_AD[4] | PHY_AD[3] | PHY_AD[2] | PHY_AD[1] | PHY_AD[0] | RSV | AD0/DA1 | WR=0 |
Byte 1  [地址高字节]: | RSV[2] | RSV[1] | RSV[0] | AD[20] | AD[19] | AD[18] | AD[17] | AD[16] |
Byte 2  [地址中字节]: | AD[15] | AD[14] | AD[13] | AD[12] | AD[11] | AD[10] | AD[9] | AD[8] |
Byte 3  [地址低字节]: | AD[7]  | AD[6]  | AD[5]  | AD[4]  | AD[3]  | AD[2]  | AD[1]  | AD[0] |
Byte 4  [数据高字节]: | DA[15] | DA[14] | DA[13] | DA[12] | DA[11] | DA[10] | DA[9] | DA[8] |
Byte 5  [数据低字节]: | DA[7]  | DA[6]  | DA[5]  | DA[4]  | DA[3]  | DA[2]  | DA[1]  | DA[0] |
```

**读帧字节映射：**

```
Byte 0  [命令字节]:   | PHY_AD[4] | PHY_AD[3] | PHY_AD[2] | PHY_AD[1] | PHY_AD[0] | RSV | BURST | RD=1 |
Byte 1  [数据高字节]: | RDA[15] | RDA[14] | RDA[13] | RDA[12] | RDA[11] | RDA[10] | RDA[9] | RDA[8] |
Byte 2  [数据低字节]: | RDA[7]  | RDA[6]  | RDA[5]  | RDA[4]  | RDA[3]  | RDA[2]  | RDA[1]  | RDA[0] |
```

> **位顺序约定**：本协议与 I2C 一致，MSB 先发送。例如 PHY_AD[4:0] 中，PHY_AD[4] 最先出现在 SDA 上，PHY_AD[0] 最后。数据字节同样高 bit 先发。

> **bit 1 读写复用**：命令字节的 bit 1 在写帧中标注为 AD0/DA1（地址帧/数据帧选择），在读帧中标注为 BURST（突发读控制）——这是同一位的读写方向复用。写时 DA1=1 为数据帧、AD0=0 为地址帧；读时 BURST=1 连续读取、BURST=0 单次读。

## 四、电路框图与物理连接

该协议的物理层就是标准 I2C，因此硬件连接与标准 I2C 完全相同。但因其目标器件是 PHY/收发器，对时序和电平匹配要求更高。

- SCL 与 SDA 均需上拉电阻（通常 2.2kΩ~4.7kΩ），上拉到 VDDIO
- 多 PHY 时所有 PHY 的 SCL/SDA 并联到同一总线上，通过 PHY_AD 区分
- 电平匹配：若 PHY 为 3.3V、主机 I2C 为 1.8V 时，必须加双向电平转换器（如 PCA9306/TXS0102）。若 PHY 支持 1.8V I2C 接口，可直接连接

## 五、核心对比

### 5.1 与标准 I2C 的详细差异

| 维度 | 标准 I2C | 扩展 PHY 管理 I2C |
|------|----------|-------------------|
| 物理层 | 2 线 SCL/SDA，开漏 | 完全相同 |
| 起始/停止条件 | START/STOP | 完全相同 |
| 设备地址 | 7 bit（或 10 bit） | 5 bit PHY_AD |
| 地址位置 | 紧跟在 START 后，第 8 位为 R/W | 分散在命令字节中，独立 WR/RD 位 |
| 寄存器地址 | 通常 1 字节（EEPROM 可 2 字节） | 21 bit（3 字节，含 RSV 填充） |
| 数据宽度 | 8 bit/字节，逐字节访问 | 16 bit（2 字节），对应一个 PHY 寄存器 |
| 突发模式 | 支持连续读写，但无显式控制位 | bit 1 读写复用：写 AD0/DA1 区分地址帧/数据帧，读 BURST 控连续读 |
| ACK/NACK | 每字节后 1 bit | 每字节后 1 bit；读末字节用 NACK 终止 |
| 寻址空间 | 128 个 7-bit 设备 × 256 字节寄存器 | 32 个 PHY × 2,097,152 个 16-bit 寄存器 |
| 典型速率 | 100 kHz / 400 kHz / 1 MHz | 100 kHz / 400 kHz（视 PHY 支持） |
| 适用芯片 | EEPROM、传感器、RTC、通用外设 | PHY、SerDes、FPGA 收发器、高端光模块 |

### 5.2 I2C 扩展协议 vs MDIO

| 维度 | MDIO (Clause 22/45) | I2C 扩展 PHY 管理协议 |
|------|---------------------|----------------------|
| 物理层 | 2 线 MDC/MDIO，SCL 推挽，SDA 开漏 | 2 线 SCL/SDA，全部开漏 |
| PHY 地址 | 5 bit（PHYAD） | 5 bit（PHY_AD） |
| 寄存器地址 | Clause 22: 5 bit；Clause 45: 16 bit + DEVAD | 21 bit（AD[20:0]） |
| 数据宽度 | 16 bit | 16 bit |
| 帧结构 | 位流（bit-oriented），固定前导码 | 字节流（byte-oriented），I2C START/STOP 定界 |
| 应答 | 转向位 TA（2 bit） | 每字节 ACK（1 bit） |
| 速率 | ≤2.5 MHz（标准） | ≤400 kHz / 1 MHz（标准 I2C） |
| 主机控制器 | 专用 MDIO 控制器（MAC 内置） | 通用 I2C 控制器 或 GPIO 软件模拟 |
| FPGA 实现 | 需 MDIO 软核或外接转换 | 可直接复用 I2C 软核，更灵活 |
| 优势 | 速度快、专用 PHY 标准、时序简单 | 复用 I2C 资源、地址空间大、线缆简单 |

> **选型建议**：若 PHY 原生支持 MDIO 且 SoC 有 MDIO 控制器，优先用 MDIO（更快、标准、驱动成熟）。若 PHY 只有 I2C 管理接口、或 SoC 没有 MDIO 控制器、或 FPGA 想复用 I2C 软核，则使用此 I2C 扩展 PHY 管理协议。

## 六、核心指标

### 6.1 I2C 时钟速率

| 模式 | f_SCL |
|------|-------|
| 标准模式 | 100 kHz |
| 快速模式 | 400 kHz |
| 快速模式+ | 1 MHz |
| 高速模式 | 3.4 MHz（需 PHY 支持） |
| 常用选择 | 100 kHz 或 400 kHz，取决于 PHY 上拉和总线电容 |

### 6.2 寻址与数据容量

| 参数 | 指标 |
|------|------|
| PHY 数量 | 32 个（5-bit PHY_AD） |
| 寄存器地址 | 21 bit（AD[20:0]），最多 2,097,152 个寄存器 |
| 数据宽度 | 16 bit（2 字节），与 MDIO 一致 |
| 一次写帧字节数 | 至少 6 字节（命令 + 3 地址 + 2 数据） |
| 一次读帧字节数 | 至少 3 字节（命令 + 2 数据） |

### 6.3 时序参数

| 参数 | 指标 |
|------|------|
| SCL 高电平时间 t_HIGH | ≥4.0 µs（100k）/ ≥0.6 µs（400k） |
| SCL 低电平时间 t_LOW | ≥4.7 µs（100k）/ ≥1.3 µs（400k） |
| SDA 建立时间 t_SU | ≥250 ns（100k）/ ≥100 ns（400k） |
| SDA 保持时间 t_HD | 0 ns（100k/400k） |
| 上升时间 t_R | ≤1000 ns（100k）/ ≤300 ns（400k） |
| 下降时间 t_F | ≤300 ns（100k/400k） |
| 总线空闲时间 | STOP 与 START 之间 ≥4.7 µs（100k）/ ≥1.3 µs（400k） |

### 6.4 一次寄存器访问耗时估算

| 操作 | 耗时 |
|------|------|
| 写 16-bit 数据 | 6 字节 × 9 时钟/字节 = 54 时钟 → 100kHz 下约 540 µs |
| 读 16-bit 数据 | 3 字节 × 9 时钟/字节 = 27 时钟 → 100kHz 下约 270 µs |
| BURST 每额外 2 bytes | 2 字节 × 9 = 18 时钟 → 100kHz 下约 180 µs |
| 400kHz 对比 | 写一帧约 135 µs，读一帧约 67.5 µs |

## 七、影响因素

I2C 的电气特性对协议可靠性影响极大。该扩展协议因数据帧较长（通常 6+ 字节），对上升时间和 ACK 时序更敏感。

| 因素 | 说明 |
|------|------|
| 上拉电阻取值 | 阻值过大会使 SCL/SDA 上升沿过慢，违反 t_R；过小会增加驱动负载。100kHz 典型 4.7kΩ，400kHz 推荐 2.2kΩ，1MHz 推荐 1kΩ |
| 总线电容 | 标准 I2C ≤400pF，但 PHY 管理应用建议 ≤200pF。总线电容 = 走线 + 引脚 + ESD + 电平转换芯片输入 |
| SCL 速率选择 | PHY 内部 I2C 接口可能只支持 100kHz。若主机配置为 400kHz，PHY 可能无法 ACK 或产生错误数据。调试时应从最低速率开始 |
| Clock Stretching | 某些 PHY 在处理内部寄存器时会拉低 SCL 进行时钟拉伸。主机 I2C 控制器必须支持 clock stretching，否则会误认为从机无响应而超时 |
| PHY_AD 地址冲突 | I2C 总线上两个 PHY 配置相同 PHY_AD 会同时响应，导致数据冲突。PHY_AD 通常由 strapped 引脚或内部 OTP 设定 |
| 电平转换器延迟 | 使用 PCA9306/TXS0102 等电平转换器时，会增加 SDA 的 RC 延迟和边沿斜率。高速模式（1MHz）下可能需禁用转换器或改用专用 I2C 缓冲器 |

> **上升时间预算**：$t_r \approx 0.8473 \times R_{pull} \times C_{bus}$（I2C 标准定义 30%~70% 上升时间）。例：R=4.7kΩ，C=100pF → tr ≈ 0.85 × 4.7k × 100p ≈ 398 ns。400kHz 模式要求 t_R ≤300 ns，此时已接近上限。因此 400kHz 应用应使用 2.2kΩ 上拉或降低总线电容。

> **典型故障模式**：读操作返回 0xFFFF 或全 0。原因排查顺序：①SDA 上拉缺失/虚焊 → ②PHY_AD 配置错误 → ③PHY 未上电/复位未释放 → ④SCL 速率过高 → ⑤总线电容过大 → ⑥读操作未执行"先写地址再读"的两步流程。

## 八、测试方法

### 测试一：功能性测试（逻辑分析仪）

1. **连接探头**：逻辑分析仪 CH0 接 SCL，CH1 接 SDA。采样率建议 ≥4 MHz（SCL 速率的 10 倍以上）
2. **配置 I2C 解码**：使用标准 I2C 协议解码即可，重点观察字节内容。若逻辑分析仪支持自定义协议解码，可设置 PHY_AD + BURST + WR/RD 的字段解析
3. **触发一次写操作**：主机发送写帧，解码器应显示：6 个数据字节 + 每字节后 ACK。检查前两个字节是否符合 PHY_AD + WR=0 + AD[20:16] 等字段
4. **触发一次读操作**：若采用"先写地址再读"的两步模式，会观察到一次写帧（无数据）后跟一次读帧；若采用单帧读，则直接观察到命令字节 + 2 数据字节 + NACK
5. **检查 ACK 位**：每个数据字节后必须有 ACK（SDA 被拉低）。若命令字节后无 ACK，说明 PHY_AD 错误或 PHY 未响应

### 测试二：信号完整性测试（示波器）

1. **测量 SCL/SDA 波形**：示波器带宽 ≥100 MHz，探头接在 PHY 端 SCL/SDA 引脚。观察上升/下降沿、过冲、振铃
2. **测量上升时间**：测量 SDA 上升沿 30%~70% 时间（I2C 标准定义），确认满足 t_R 要求
3. **测量 ACK 位**：在第 9 个时钟周期，SDA 应被从机拉低。若 ACK 位仍为高，说明从机未响应
4. **检测 Clock Stretching**：观察 SCL 低电平是否被从机拉低延伸。若 SCL 低电平宽度异常增大，说明 PHY 在拉伸时钟

### 测试三：软件层验证（Linux 环境）

```bash
# 1. 确认 I2C 总线和设备存在
i2cdetect -y 0          # 扫描总线 0，查看 PHY 是否响应
i2cdump -y 0 0x10       # 按标准 I2C 方式 dump 设备地址 0x10 的寄存器

# 2. 手动发送字节（需要知道 PHY 的 I2C 设备地址映射）
i2cset -y 0 0x10 0x00 0x80  # 写 1 字节（仅示例，实际协议需适配）
i2cget -y 0 0x10 0x00       # 读 1 字节（实际扩展协议需按自定义帧发送）

# 3. 使用 Python 脚本通过 smbus 模拟自定义协议
import smbus
bus = smbus.SMBus(0)
bus.write_i2c_block_data(DEV_ADDR, CMD_BYTE, [ADDR_H, ADDR_M, ADDR_L, DA_H, DA_L])
```

**推荐设备**：

- 逻辑分析仪：Saleae Logic、DSLogic、Kingst LA2016（支持 I2C 解码）
- 示波器：≥100 MHz，最好有 I2C 触发/解码功能（如 Siglent、Rigol、Keysight）
- 软件工具：Linux i2c-tools、Python smbus2、逻辑分析仪配套软件

## 九、注意事项

| 注意事项 | 说明 |
|----------|------|
| 🔌 双上拉不可省 | SCL 和 SDA 都需要上拉电阻。缺任何一个都会导致总线无法回到高电平，I2C 无法工作。注意 MDIO 只有 SDA 需要上拉，SCL 推挽不需要——这是两者的显著区别 |
| 📋 读操作需先写地址 | 若 PHY 的读协议为"两步读"，必须先发送一次写帧设定地址（DA 不发送），再重新 START 发送读帧。直接发读帧可能返回当前寄存器或错误数据 |
| 🔄 BURST 与 NACK 配对 | 读操作时，主机必须在每个 16-bit 数据的末尾决定是否继续：继续则 ACK 低字节，停止则 NACK 低字节。BURST=1 只是从机允许突发，实际终止权在主机 |
| ⚡ 速率从低到高 | 调试时先用 100kHz 确认通信正常，再尝试 400kHz。高速 PHY 对 I2C 的 ACK 时序可能更严格，不要盲目提速 |
| 🌡️ 保留位按 datasheet 写 | RSV、RSV[2:0] 等保留位不能随意填 1。某些厂商用保留位做使能、地址扩展或模式选择，必须按 datasheet 配置 |
| 🔍 区分标准 I2C 和扩展协议 | 用标准 I2C 工具（如 i2cdetect）可能无法识别该 PHY，因为设备地址格式不是 7-bit。需使用厂商专用工具或 GPIO 模拟自定义时序 |

### 常见问题速查表

| 现象 | 可能原因 | 排查方法 |
|------|----------|----------|
| 命令字节后无 ACK | PHY_AD 错误 / PHY 未上电 / SCL 速率过高 | 检查 PHY_AD strapping；万用表查供电；降速到 100kHz |
| 写数据后读回不同值 | 地址未正确写入 / 保留位配置错误 | 逻辑分析仪核对写帧地址段；查 datasheet 保留位定义 |
| 读数据全 0 或全 1 | 未先写地址 / 地址超出范围 | 尝试两步读；确认地址寄存器有效范围 |
| 偶发数据错误 | 总线电容过大 / 上拉不合适 / EMI 干扰 | 示波器测上升时间；调整上拉；缩短走线 |
| BURST 模式不工作 | BURST 位未置 1 / PHY 不支持 | 查 datasheet 是否支持 burst；核对命令字节 BURST 位 |
| SCL 低电平异常拉长 | Clock stretching 未处理 | 主机控制器启用 clock stretching 支持或加超时 |

## 十、选型指南

### 场景一：选择 PHY 管理接口

| 场景 | 推荐接口 | 理由 |
|------|----------|------|
| PHY 原生带 MDIO，SoC 有 MDIO 控制器 | MDIO | 速度快、标准、驱动成熟、硬件简单 |
| PHY 只提供 I2C 管理接口 | I2C 扩展协议 | 别无选择，需按 PHY 自定义协议实现 |
| FPGA 设计，无 MDIO 控制器 | I2C 扩展协议 | 复用 I2C 软核，节省 FPGA 资源 |
| 需要大量连续寄存器 dump | MDIO Clause 45 或 I2C BURST | 突发模式可大幅减少通信时间 |
| 长距离板间管理 | I2C 缓冲/扩展 | MDIO 不适合板间长距离 |
| 车载以太网 PHY | MDIO Clause 45 | 车载 PHY 通常以 MDIO 为主接口 |

### 场景二：I2C 控制器选型

| 选型维度 | 建议 |
|----------|------|
| 多字节 buffer | 控制器应支持发送 ≥6 字节 block，接收 ≥2 字节 block |
| Clock stretching | 必须支持从机拉低 SCL 时的等待，否则读取不稳定 |
| START/STOP 控制 | 需支持重复 START（Repeated START）用于两步读 |
| 速率配置 | 支持 100kHz/400kHz/1MHz 可配置 |
| GPIO 软件模拟 | 若控制器不灵活，可用 GPIO 位操作模拟时序，但占用 CPU |

### 决策流程

1. **确认 PHY 接口**：查 datasheet 看 PHY 是否支持 MDIO、I2C 或两者。优先选择 PHY 原生接口
2. **确认主机资源**：SoC/FPGA 是否有 MDIO 控制器？若只有 I2C，则用 I2C 扩展协议
3. **分配 PHY_AD**：按 PHY 数量分配唯一 5-bit 地址，注意 strapping 引脚配置
4. **硬件设计**：SCL/SDA 双上拉、电平匹配、控制总线电容
5. **软件实现**：根据 datasheet 自定义 I2C 帧格式，实现读/写/BURST 函数；用逻辑分析仪验证

> **选型总结**：此 I2C 扩展 PHY 管理协议是标准 I2C 物理层 + 自定义应用层的组合。它的核心价值在于复用 I2C 硬件资源来访问大寄存器空间的 PHY/收发器。在硬件设计正确、协议实现精确的前提下，它可以作为 MDIO 的有效替代方案；但若 PHY 和 SoC 都支持 MDIO，MDIO 仍是更优选择。
