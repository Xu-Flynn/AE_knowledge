产品概述与定位

Retimer（重定时器）是一种高速信号再生芯片，位于两个高速SerDes链路之间。与Redriver（仅信号放大/均衡）不同，Retimer执行完整的CDR（时钟数据恢复）和信号重新发送，彻底消除累积抖动。它是数据中心背板互联、长距离PCB走线和光模块Host侧信号清洁的关键组件。

📌 产品定位

产业链位置：两个SerDes链路之间，信号中继/再生节点

核心价值：彻底消除累积抖动，而非仅放大信号

本质功能：CDR重定时 + 信号重新发送

🎯 典型应用场景

  • 数据中心交换机背板互联
  • 长距离PCB trace信号延伸（>15 inch）
  • 线缆/背板中继
  • 光模块Host侧信号清洁
  • PCIe 5.0/6.0 Retimer
  • 400GAUI-8/800GAUI-8 信号再生

核心工作原理

Retimer 的核心任务是恢复纯净时钟 + 重新定时发送。与 oDSP 或 Redriver 不同，Retimer 的设计重心在于 CDR 的抖动消除能力和极低转发延迟。

📥 Retimer 信号处理流程

图 2-1 | Retimer 信号处理流水线（单通道）

处理步骤详解：1) CTLE: 模拟域补偿Nyquist频率附近信道损耗；2) CDR: 从输入数据恢复纯净时钟，消除输入抖动（含RJ和DJ）；3) DFE: 数字域消除残留ISI；4) Elastic Buffer: 跨时钟域同步（恢复时钟→本地发送时钟）；5) TX FIR: 预加重补偿输出信道损耗；6) 输出驱动下游信道。

🔑 抖动消除机制 — Retimer的核心价值

Retimer的抖动传递函数（JTF, Jitter Transfer Function）：

Jitter_Out = JTF × Jitter_In + Jitter_Generated

其中 JTF 由 CDR 的低通特性决定：

  • f << CDR_BW：JTF ≈ 0 dB — 低频抖动通过（CDR 可跟踪）
  • f >> CDR_BW：JTF → −40 dB/dec — 高频抖动被大幅抑制
  • Jitter_Generated：Retimer 自身产生的底噪抖动（RJ <250fs RMS）
💡 关键认知：Retimer 的 CDR 带宽就是抖动抑制的性能边界。CDR_BW 越高（如 5~10MHz），对低频抖动跟踪越好但高频抑制变弱；CDR_BW 越低（如 1~2MHz），高频抑制更好但低频抖动可能积累。工程上需在跟踪能力和抑制能力之间权衡。

核心模块深度解析

一、CTLE (连续时间线性均衡器)

CTLE 是一种高通滤波器，在模拟域对输入信号进行初步高频补偿，扩展 CDR 的接收范围。其频率响应提供频率相关的增益：

  • DC 增益：0dB（低频直通）
  • 高频 Peaking：6~18dB @ Nyquist 频率（可编程调节）
  • Peaking 频率：可调，需匹配信道损耗拐点
  • 级数：通常 2~4 级级联，逐级补偿
调节参数功能典型范围
DC gain低频增益调节−3 ~ +3dB
Peaking gain高频补偿量6 ~ 18dB
Peaking frequency补偿频点位置5~30GHz 可调
输出共模电压匹配后端 CDR 输入0.4~0.8V 可编程

二、CDR (时钟数据恢复) — Retimer 的灵魂

CDR 是 Retimer 最核心的模块，负责从含有严重抖动的输入信号中恢复出纯净时钟，并用该时钟重新采样数据，从而实现抖动消除。

Retimer CDR 与 oDSP CDR 对比：

特性oDSP CDRRetimer CDR差异原因
时钟来源从 ADC 采样数字数据恢复从模拟信号直接恢复Retimer 无 ADC
PD 类型MM-PD (数字)Hogge / Linear PD (模拟) 或 MM-PD模拟前端匹配
抖动要求<200fs RMS<250fs RMS（稍宽松）级联场景有更多余量
锁定范围±350ppm±500ppm（更宽）需兼容更多时钟源
锁定时间<100μs<50μs（更快）需支持热插拔场景

Retimer CDR 特殊考量：

  • 多速率支持：需支持 10G / 25G / 50G / 100G per lane 多种速率
  • 快速锁定：热插拔场景要求 CDR 在 <50μs 内完成锁定
  • 参考时钟不精确：可能从 Host 恢复，时钟质量不可控
  • JTF 峰值要求：JTF 峰值 <0.1dB — 这意味着 CDR PLL 不能有任何增益峰值
相位误差 = e(n) · d(n−1) − e(n−1) · d(n)   |   二阶 PLL: Kp + Ki/s

三、DFE (判决反馈均衡器)

Retimer 中的 DFE 与 oDSP 类似但有所简化。由于 Retimer 面向背板/PCB trace 等较短链路，ISI 通常不如光纤信道严重：

  • 通常 1~3 tap
  • 重点补偿短距信道的后向 ISI
  • 通常不需要 MLSD（转发延迟要求更严，MLSD 增加数十 UI 延迟）
  • 自适应 LMS 算法收敛
y[n] = x[n] − Σ(k=1 to 3) d[n−k] · b[k]   |   PAM4 判决阈值: −2, 0, +2

四、弹性缓冲 (Elastic Buffer / FIFO)

Elastic Buffer 是 Retimer 区别于 Redriver 的关键模块之一。它在恢复时钟域（CDR 恢复的时钟）和本地发送时钟域（PLL/CMU 产生的 TX 时钟）之间进行数据同步，实现真正的跨时钟域重定时。

参数典型值说明
FIFO 深度32~128 UI决定可容忍的最大频偏和延迟
频率偏差容限±500ppm覆盖恢复时钟和 TX 时钟之间的最坏频差
上溢/下溢保护插入/删除 Skip 符号FIFO 满时删 Skip，空时插 Skip
延迟贡献1~5ns约占总延迟的 30~50%
⚠️ 关键约束：FIFO 深度越大 → 可容忍频偏越大 → 但延迟也越大。对于延迟敏感应用（HPC/金融交易），需在频偏容限和延迟之间仔细权衡。

五、TX FIR (发送端预加重)

TX FIR 对输出信号预补偿，驱动下游信道。与 oDSP TX DSP 类似但更简单（无 FEC 编码、无 NLC 等）：

  • 3~5-tap FIR 滤波器
  • c_main：0~63（主抽头系数）
  • c_pre / c_post：−20 ~ +20（前/后向抽头）
  • 输出幅度：200~1200 mVppd 可编程
  • 支持 Pre-emphasis −6 ~ +12dB 范围
Vout[n] = c_pre·Vin[n+1] + c_main·Vin[n] + c_post·Vin[n−1]

Retimer vs Redriver 全面对比

🔷 Retimer (重定时器)

  • 信号处理：CDR + 信号重新生成
  • 抖动消除：完全（CDR 重定时）
  • 延迟：1~10ns（含 FIFO）
  • 功耗：0.5~1W / lane
  • 协议感知：部分（需 CDR 锁定到协议速率）
  • 适用距离：长距延伸（>20dB 损耗）
  • 复杂度：高（含 CDR / DFE）
  • 成本：中-高

🟢 Redriver (重驱动器)

  • 信号处理：模拟均衡 + 放大
  • 抖动消除：有限（仅均衡）
  • 延迟：<100ps
  • 功耗：<0.3W / lane
  • 协议感知：无（透明传输）
  • 适用距离：短距延伸（<10dB 损耗）
  • 复杂度：低
  • 成本：低

💡 工程决策直觉："信号能到就 Redriver，到不了就 Retimer。Redriver 是信号放大器，Retimer 是信号再生器——本质区别在于要不要 CDR。当链路抖动预算紧张、或需要跨时钟域时，Redriver 无能为力，必须上 Retimer。"

✅ Retimer 关键共同影响因素（所有高速重定时芯片均适用）：
  • CDR 环路参数：PLL 带宽和相位余量直接影响 JTF 形状 — 带宽太高 → 高频抖动抑制不足；带宽太低 → 锁定时间长
  • 参考时钟质量：RefClk 相噪通过 CMU 放大后成为 TX 输出抖动的基底 — RefClk RJ 要求 <100fs RMS
  • 电源完整性 (PDN)：模拟前端 (CTLE/CDR) 对电源纹波极度敏感 — 100μV 纹波可导致数 fs RJ 恶化
  • 信号完整性 (SI)：PCB trace 阻抗失配 → 反射 → ISI → 增加 CDR 输入抖动 → Jitter_Generated 增大
  • FIFO 深度 vs 延迟：深度越大可容忍频偏越大，但延迟也越大 — 延迟敏感场景需小深度 + 精确频率规划

📐 7.1 抖动传递测试 (Jitter Transfer) — 核心测试

测试原理：测量 Retimer 的 JTF（Jitter Transfer Function），即输出抖动与输入抖动之比随频率的变化。这是评估 Retimer 核心性能最重要的测试。

JTF 测试框图

JTF 测试步骤

1
系统校准与预热

BERT + 示波器预热 >30min；校准电缆损耗（去嵌入 S 参数）；确认 DUT 供电正常，CDR Lock Status=1。

2
基准抖动测量（无 SJ）

SJ 关闭，测量 Retimer 输入和输出的固有抖动（RJ + DJ），作为 JTF 计算的基准参考。

3
SJ 频率扫描

SJ 频率扫描: 10kHz, 50k, 100k, 500k, 1M, 5M, 10M, 50M, 100MHz；每个频点 SJ 幅度 0.1~0.5UI（保证 CDR 不脱锁）。

4
每个频点测量

测量 Retimer 输出抖动 Jitter_Out(f) 和输入抖动 Jitter_In(f)；计算 JTF(f) = 20·log₁₀(Jitter_Out / Jitter_In) [dB]。

5
绘制 JTF 曲线 & 判定

绘制 JTF vs 频率曲线（双对数或半对数）；判定：JTF 峰值 <0.1dB；高频 (@10MHz) 抑制 >20dB；CDR_BW 处过渡平滑无 peaking。

6
三温重复

在 −40°C / +25°C / +85°C 三温下重复 JTF 扫描，验证温度对 CDR 环路参数（BW、相位余量）的影响。

🔴 7.2 抖动容限测试 (JTOL) — 级联场景

类似 oDSP CDR 抖动容限测试，但需额外验证Retimer 级联场景：

级联验证要求：两个 Retimer 串联后，级联抖动不累积超过单个 Retimer 抖动预算的 2×。如果每个 Retimer 的 JTF 峰值 <0.1dB，理论上级联 JTF <0.2dB。

🟡 7.3 转发延迟测试

方法：使用示波器的 TDR/TDT 模式测量 Retimer 的转发延迟。

1
激励信号

阶跃信号或窄脉冲注入差分输入端；阶跃上升时间 <20ps（远小于 Retimer 延迟）。

2
时间差测量

示波器双通道同时监测输入和输出；测量输入阶跃的 50% 点到输出阶跃的 50% 点时间差。

3
判定标准

400G 模式: <5ns；800G 模式: <8ns；多次测量取最大/均值/标准差。

🟢 7.4 多速率兼容性测试

Retimer 需支持多种协议速率，验证 CDR 在各速率下均能正常锁定：

上电: Vcore(0.8V) → 等待 >10ms → Vio(1.2V) → 等待 >10ms → Vana(1.8V)；断电: 反向！绝对禁止颠倒，否则可能永久损坏芯片！

🕐 参考时钟质量

频率: 156.25MHz LVDS；相噪: −150dBc/Hz @10kHz；RJ: <100fs RMS (12k~20MHz)；精度: ±50ppm。RefClk 质量直接影响 CDR 抖动底噪。

🎯 CDR 锁定确认

测试前务必确认 CDR Lock Status=1；未锁定时 BER 和 JTF 测试完全无意义；锁定后等待 >50μs 让 DFE 系数完成自适应收敛。

🔗 级联抖动监控

多级 Retimer 级联时，每级输出抖动需分开监测；JTF 峰值超标 0.1dB 即可能导致级联失败；建议每级设置相同的 CDR 环路参数。

⏱ 延迟敏感设计

HPC/金融交易等延迟敏感应用需仔细评估 FIFO 深度；FIFO 深度从 128UI 降到 32UI 可节省 ~2ns 延迟但频偏容限降为 ±125ppm。

🔄 多速率兼容验证

不同速率下 CDR_PLL 参数可能需分别优化；25G/53G/106G 三档速率切换时验证 CDR 锁定时间和稳定性；检查速率自动检测功能是否可靠。

🔵 Retimer 专项注意事项

📡 输入信号质量要求

Retimer 不是"万能修复器"—输入信号眼图需至少张开 30mV/0.1UI；完全闭合的眼图 Retimer 也无法恢复；CDR 需要最小摆幅来锁定。

🔍 电缆/PCB 去嵌入

JTF 测试中电缆和 PCB trace 会引入额外抖动；使用 VNA 提取 S 参数 → 示波器去嵌入功能补偿；否则 JTF 测量结果偏悲观。

⚡ 电源隔离与去耦

AVDD 与 DVDD 分开供电；模拟前端 CTLE/CDR 就近放 100nF+10μF 去耦；数字 I/O 开关噪声通过衬底耦合到模拟前端 → RJ 恶化。

🌡️ 温度对 JTF 的影响

高温 → CDR PLL 环路参数漂移 → JTF 形状变化；全温范围 (−40~+85°C) JTF 峰值仍需 <0.1dB；温漂补偿电路是必备设计。

🚨 Retimer 测试最常见错误：
  • CDR 未锁定时测 JTF/BER：结果完全无意义，数据如同随机噪声
  • SJ 幅度过大导致 CDR 脱锁：JTF 测试中 SJ 幅度应控制在 0.1~0.3UI 以内
  • 忽略 FIFO 溢出/空：频偏超出 FIFO 深度时出现 Skip 符号 → BER 虚高，实际不是信道问题
  • 测试电缆未去嵌入：测出的是"Retimer + 电缆"的组合 JTF，不是 Retimer 自身的 JTF
  • 未区分 Retimer 自身抖动和输入残留抖动：输出抖动 = 输入抖动 × JTF + 自身抖动；不做 SJ 扫描分离不出两个分量

选型与应用指南

🔷 何时选用 Retimer？何时选用 Redriver？

✅ 选用 Retimer 的场景

  • 信道损耗 >15dB（需 CDR 重新定时）
  • 链路抖动预算紧张，需消除累积抖动
  • 需要跨时钟域同步（FIFO / Elastic Buffer）
  • 多级级联延伸场景
  • 400GAUI-8 / 800GAUI-8 标准接口
  • 协议速率需 CDR 主动锁定（非透明传输）
  • 输出信号质量要求高（RLM>0.92, RJ<250fs）

✅ 选用 Redriver 的场景

  • 信道损耗 <10dB（模拟均衡+放大足够）
  • 延迟敏感应用（<100ps），如 HPC 互联
  • 功耗预算极紧张（<0.3W/lane）
  • 协议透明传输需求（无需 CDR 锁定）
  • 成本敏感，可接受有限抖动改善
  • PCB trace 短距延伸（<10 inch）
  • 多协议同时通过（Redriver 无协议感知）

💡 AE 工程直觉 — Retimer 选型口诀：
  • "抖动是敌人，CDR 是武器" — Retimer 的核心价值永远在抖动消除，不是信号放大
  • "JTF 是 Retimer 的体检报告" — JTF 峰值 <0.1dB 是硬指标，超标即不合格
  • "级联要谨慎" — 两个 Retimer 串联 ≈ JTF 平方，峰值 0.1dB → 级联峰值 <0.2dB
  • "延迟和频偏不可兼得" — 小 FIFO = 低延迟 + 低频偏容限；大 FIFO = 高延迟 + 高频偏容限
  • "时钟是天花板" — RefClk 相噪决定了 TX 输出抖动的下限，选 Retimer 先看 RefClk 规格
